Notes and open questions

Sankey: which quantity?

The ribbons above use docs/s, because docs are conserved: the 8k docs/s coming down equals the 8k docs/s the persister sends back up as files. The merger’s ribbon is wider (≈20k docs/s re-merged) because it rewrites the same docs repeatedly, so write amplification shows up as width. Writes to disk are a second, gray kind of ribbon in MB/s. Mixing two units is the weak spot. Arrows avoid the question, but they lose the amplification story.

One subtlety: what goes “up” to the introducer is metadata (swap these segments for that one), not bytes. With docs/s as the unit, the ribbon still means something: “these docs now live in a different segment.”

Stacked workers

Only worker 0 is fully drawn. When the story needs it (for example, the herder blocking all four, or the CPU-bound ingest), the stack could fan out sideways into four panels, then collapse back afterward.

Zoom

Here the camera is driven by the story: each step declares a region of the canvas. We could also let readers pan and zoom freely, with a “recenter” button. The canvas can grow taller as chapters add detail (queries, rollback points), because the camera only ever shows part of it.
